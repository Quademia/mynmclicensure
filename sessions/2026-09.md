### Learned (→ AGENTS.md workarounds)

  (React 19). The register form's first submit only opens a confirm

  someone out redirects to `/logout?via=gate` (a Route Handler).

  file later must be copied across by hand.

### Sam's question 2 — dev and prod as two schemas in one Supabase project

Rejected, and Sam dropped it. A schema separates *products* within an
environment; it cannot separate *environments*, because the dangerous
shared things are project-wide, not schema-scoped: **one `auth.users`
table** (a dev test signup would sit beside a paying student, with no
way apart), one anon + service-role key pair (a leaked dev key is the
prod key), one Storage, one set of auth/email/redirect settings, one
connection pool and resource limit, and backups/restores per project.
The right axis is one project per environment, one schema per product
— which is exactly gamma's pair as it stands, at no extra cost. The
only cheaper shape is local Supabase (Docker) for dev with prod alone
in the cloud, which would leave the deployed `licensure-dev` Worker
with no database; not taken.

### Session mode (Sam asked; answer worth keeping)

Claude Code's "project" is the folder a session is opened in: that
folder's `CLAUDE.md` is auto-loaded, its memory directory is separate,
its history is separate. **One session per repo, opened in that repo's
folder.** Attaching another repo's folder to a session is right for
cross-repo discussion (today's morning) and wrong for building (today's
afternoon — the launcher symptom above). Codex has the same shape via
`AGENTS.md`. The memory Claude wrote today lives under the MyNclex
project and points here; a fresh licensure session starts from this
log, which is the design.
